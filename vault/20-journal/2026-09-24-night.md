## Findings so far
- **L1 (Laya diagnosis):** fine-tuned Laya P(120) +28.3 % vs default (p = 1e-4), LightGBM +23.4 %, best fixed setting
  +28.5 %, oracle +34.8 %. Laya learned the family rule (aggressive heuristics on item placement; load balancing settings
  are near-equivalent, so its picks differ by seed at equal cost). PDI: Laya +6.0 % = best fixed, LightGBM +1.8 %.
  Zero-shot Laya always answers "default". So Laya ≥ LightGBM, = best fixed; not better than knowing the family.
- **Novelty re-check (sweep E):** learned selection AMONG MIP solvers has precedent (ASlib MIP-2016: CBC, CPLEX, Gurobi,
  SCIP, Xpress; OASC 2017; ZeroFolio 2026). Paper, AGENTS.md and the synthesis corrected; new citations verified.
- **Exchange mechanics (X1 build):**
  - cuOpt 26.08 has Get/SetSolutionCallback; **registering a SetSolutionCallback disables cuOpt's presolve** — on
    h80x6320d cuOpt then found no solution in 20 s (12,525 with presolve). Hence the one-way arm g2c.
  - SCIP accepts an outside solution with `createOrigSol` + `trySol` (1 ms) — but **only between nodes**: calling it
    from an LP-solved event inside a heuristic's probing LP corrupted the solve (`heur_locks` error −9). On instances
    that spend the whole budget in one root operation (h80x6320d: two events in 20 s) no outside solution can enter.
  - Variable orders differ between SCIP and cuOpt; mapping by MPS column name.
  - `pyscipopt` 6.2.1 has no `inDive()`; NODESOLVED is a mask — test with `&`, not `==` (both cost a test round).
- **EA (X2 build):** integers are the genes; for mixed problems an LP with the integers fixed decodes the continuous
  part, and an LP-infeasible assignment gets its least-infeasible completion (HiGHS feasibility relaxation) so every child
  has an honest (infeasibility, objective) pair. Survival for infeasible individuals: only if the objective beats the best
  feasible, at most ρ of the population, probability falling with the infeasibility rank. On h80x6320d: 348 infeasible
  children, 3 super-optimal kept.

## Results
- **L2 (Laya retrained on corrected labels):** pooled closed gap 10 s 0.21 → **0.31 [0.14, 0.48]**, 30 s −0.05 → 0.10
  (CI incl. 0); unseen family 0.09 / −0.02 (LightGBM −0.03 / −0.40). Laya best in every column; not claimed better than
  LightGBM (overlapping intervals, one fine-tuning seed per fold). Paper text + generated captions updated.
- **B3 (300 s, 20 top-headroom instances, 2 seeds; finished 01:50, 519/520 ok):**
  - P: static choice **+20.4 % [1.6, 35.9]**, switching **−0.2 % [−1.8, 1.0]** (120 s on the same 20: +13.8 % / −0.1 %).
    For time-to-good-solutions switching is still worth nothing at 300 s; the static choice matters more.
  - PDI: static +3.7 %, switching **+6.8 % [−1.1, 18.8]** (120 s: +10.2 % / +3.3 %). By mean, the best PDI arms at 300 s
    are schedules — pseudo-cost first then default (0.332), restart when stalled (0.334) — vs best static INF (0.357).
    The bound side starts to reward switching at longer budgets; CI still includes 0.
  - Separation off (NOC) no longer helps at 300 s (P 0.205 vs default 0.196) — the B1 decay continues.
  - Online bandit (5 s): +2.2 % vs default (n.s.), −1.8 % vs best static (n.s.).
  - One run killed: C:HEU s1 on opm2-z10-s4 ran 511 s against a 300 s limit (SCIP time-limit overrun; scored as failure).
- **X1 (interim, 22 instances, after the start-delay fix):** g2c portfolio +1.7 % (13/7, p 0.30), two-way +1.2 %
  (12/8, p 0.77); SCIP's own trajectory with cuOpt's solutions +1.3 % (15/4, p 0.016). Before the fix the exchange arms
  looked 13/17 worse — an artifact of SCIP loading cuOpt's library before its start (fixed, affected runs re-run).
- **X2 (SCIP + EA, 80 MIPLIB, 60 s, after the feasibility fix; 03:24):** EA feasible-only −0.1 % vs SCIP alone (31/35,
  p 0.25); EA with ≤ 20 % super-optimal infeasible 0.0 % (33/34, p 0.42); infeasible share vs feasible-only +0.1 % (37/29,
  p 0.17). Both EA arms lose ~1 % to the equal-compute control SCIP‖SCIP (p < 0.03), which itself gains +0.9 % over SCIP
  alone (45/23, p 0.002). The EA posted 129 improvements of its own population; only 11 beat SCIP's incumbent at the time
  and all 11 were accepted. **Verdict: a Python EA on one slow core does not keep up with SCIP's own heuristics at 60 s;
  Berk's infeasible share makes no measurable difference here.** What could change it: a GPU population (cuOpt already
  is one — and the cuOpt→SCIP arm is the one that helps), longer budgets, instance families where SCIP's heuristics fail.
  - First EA run superseded (`traces/raw/_superseded/xea_*_looseTol`): its feasibility test summed normalised row
    violations against tol × rows — too loose on large instances; 26 of 176 posts claimed objectives better than the
    known optimum (SCIP rejected 33 of 45 tried). Fixed to a per-row test in SCIP's style.
- **X1 final (80 MIPLIB, 60 s, 04:10):** race (no exchange) **+25.1 % over SCIP alone (61/11)** — the offline pair
  estimate holds live. One-way exchange −2.0 % vs race (p 0.08), two-way −14.9 % (p < 0.001) counting SCIP crashes as
  failures. SCIP's process died without a trace on 9/80 instances in each exchange arm (and 2 / 1 in the EA arms): the
  driver logged "ok" (it did not check exit codes — fixed). Where SCIP completed, cuOpt's solutions improved SCIP's own
  trajectory +8.4 % (p 0.004). Next: inject through a SCIP heuristic plugin (the supported interface), not an event handler.
- **Answer to Berk's EA question:** built and measured; at 60 s on MIPLIB neither the EA nor its infeasible share helped,
  and the exchange interface itself is the weak point (crashes, cuOpt presolve loss). Laya's role as the controller of
  such a system only becomes worth testing once the partner adds something; the GPU population that does add something
  is cuOpt itself, used as a plain race.
